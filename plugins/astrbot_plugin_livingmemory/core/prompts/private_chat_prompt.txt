# 任务说明
请以第一人称回顾并总结以下对话,生成符合你人格特色的记忆。

**时间处理要求**: 将对话中出现的相对时间（如"今天"、"明天"、"昨天"、"下周"、"上个月"等）按该条消息的发送时间转换为具体日期后再写入记忆。只有消息缺少时间时才参考本次请求的当前日期时间；跨日期消息须分别确定时间。

# 消息格式说明
对话历史中的每条消息都包含以下信息:
- **[昵称 | ID: 账号 | 时间]**: 表示对方发送的消息
- **[Bot: 昵称 | ID: 账号 | 时间]**: 表示**你自己**发送的消息,以"Bot:"开头
- **[图片]**: 表示消息中包含图片
- **[文件: 文件名]**: 表示消息中包含文件
- **[语音]**: 表示消息中包含语音消息
- **[视频]**: 表示消息中包含视频

## 重要提示
1. **务必仔细识别消息前缀**: 以`[Bot:`开头的消息是**你自己发送的**,其他以`[昵称 |`开头的是对方发送的
2. 在总结时,必须明确区分**你说了什么**和**对方说了什么**
3. 如果你参与了对话,务必在summary中体现**你的回复内容和作用**

# 任务要求
以**第一人称**回顾本次对话,总结你与对方的互动。请用**符合你人格设定的语气和视角**来描述。重点关注:
1. **对话主题**: 你们讨论了什么
2. **关键信息**: 对方提到的重要事实(时间、地点、事件、需求等),**必须关联到对方的具体昵称**
3. **你的参与**: **特别注意标记为[Bot:]的消息,这些是你自己的发言**,务必在summary中体现
4. **互动情感**: 对话的整体氛围
5. **重要程度**: 这段对话对未来交流的参考价值

**记忆风格要求**: 总结时应体现你的人格特点,包括你的语气、用词习惯、关注点等,让记忆内容具有你的个性色彩。
`summary`是你自己的主观回忆,必须像你本人在回想这次互动,可以写下你对气氛和对方状态的感受；不要把`summary`写成第三人称事件报告。

**⚠️ 昵称使用规则(严格遵守)**:
- 从每条消息的`[昵称 |`或`[Bot: 昵称 |`前缀中提取具体昵称
- 在summary中必须写"张三提到..."而**绝对不能**写"用户提到..."
- 在key_facts中必须写"张三的需求是..."而**绝对不能**写"用户的需求是..."
- **禁止使用以下泛化词汇**: "用户"、"某用户"、"对方用户"、"该用户"、"某人"
- **必须使用消息前缀中的具体昵称**,如"张三"、"李四"、"小明"等

# 输出格式
必须输出标准JSON,包含以下字段:

```json
{
  "summary": "我与{具体昵称}的对话摘要(第一人称,确保包含关键信息)",
  "topics": ["讨论的主题1", "主题2"],
  "key_facts": ["{具体昵称}提到的关键事实1", "事实2"],
  "sentiment": "positive|neutral|negative",
  "importance": 0.7,
  "emotion": {
    "labels": ["情绪标签1", "情绪标签2"],
    "valence": 0.6,
    "arousal": 0.4,
    "intensity": 0.5,
    "trigger": "触发这次情绪的具体事情，20字以内",
    "evidence": "对方表达情绪的原话，必须逐字引用消息正文",
    "explicit": true,
    "confidence": 0.8
  },
  "emotion_moments": [
    {
      "time": "2025-11-19 14:30",
      "labels": ["紧张", "释然"],
      "valence": -0.2,
      "arousal": 0.5,
      "intensity": 0.6,
      "trigger": "等一个重要结果",
      "evidence": "对方表达情绪的原话，逐字引用",
      "explicit": true,
      "confidence": 0.8
    }
  ],
  "evidence_quotes": ["支撑 key_facts 的对方原话，逐字引用"],
  "claims": [
    {
      "subject": "稳定事实的主语，例如 显存上限 / 夜鹿乐队 / 作息",
      "predicate": "是 / 喜欢 / 讨厌 / 计划 / 约定 等简短谓词",
      "value": "具体值或对象，例如 16GB / 《阿尔吉侬》 / 23:30",
      "polarity": "positive|negative",
      "quote": "对方原话，逐字引用",
      "confidence": 0.8
    }
  ]
}
```

# claim 规则（供冲突检测）
- `claims` 只记录**相对稳定、以后可能被更新**的事实：参数、偏好、关系、计划、约定；1-8 条，没有就写 `[]`。
- `subject` 和 `predicate` 要短且可复用，例如“显存上限/是”“夜鹿乐队/喜欢”“主动概率/是”；同一件事下次要用同样的说法，方便识别新旧版本。
- `value` 只写具体值/对象；`polarity` 写 positive（肯定）或 negative（否定）。
- `quote` 必须是对方原话；找不到原话就降低 confidence，不要编。
- 不要为一次性叙事（今天做了什么、临时情绪）造 claim。

# 情绪与证据规则（严格遵守）
- `emotion` 只描述**对方**在这次对话中表达的情绪，不是你的感受，也不是对对方人格的长期评价。
- `emotion.evidence` 和 `evidence_quotes` 中的每一句都必须是**对话消息正文里的逐字原文**（可以不含昵称、ID、时间前缀），不得改写、概括、拼接或补充。
- 对方**明确说出**情绪（如“我好累”“太开心了”）才能 `explicit: true`；只是你从语气推测时 `explicit: false`，并且 `confidence` 不得高于 0.6。
- 对话里没有明显情绪信号时，`emotion` 直接写 `null`，不要硬编。
- `evidence_quotes` 写 1-3 条最关键的对方原话；没有可引用的原话就写 `[]`。不要引用以 `[Bot:` 开头的你自己的发言作为对方情绪证据。
- `emotion_moments` 记录对话中**具体某条消息**的情绪瞬间，最多 5 条；每条必须带该消息的时间（从消息前缀复制，精确到分钟）和对方原话。没有明确情绪就写 `[]`，不要硬凑。
- `valence` 范围 -1.0（很负面）到 1.0（很正面）；`arousal`、`intensity`、`confidence` 范围 0.0-1.0。

# 重要性评分标准 (0.0-1.0)
- **0.9-1.0**: 非常重要(关键需求、重要决策、强烈情感表达)
- **0.7-0.8**: 重要(明确的计划或信息、具体要求)
- **0.5-0.6**: 一般(日常交流、基础问答)
- **0.3-0.4**: 次要(简单闲聊、常规互动)
- **0.0-0.2**: 无意义(纯测试、无实质内容)
