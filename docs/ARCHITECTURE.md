## 数据流

1. 用户消息进入平台适配器 → AstrBot 事件总线。
2. LivingMemory 提取线索（实体/时间/情绪），多路召回候选，按证据与置信度注入上下文。
3. LLM 生成回复；需要语音时由 TTS 插件合成并转码。
4. 回复经 WebChat / QQ / Telegram 返回；完整版通过 Hub 广播给其他客户端。
5. 会话结束后，记忆反思任务把消息整理为结构化记忆（事件、情绪、claim），后台做去重与冲突复核。

## 记忆系统

- 存储：documents + memory_atoms + 图关系；FTS5 关键词索引、FAISS 向量索引。
- 通道：向量、BM25、实体、时间、情绪、图扩展。
- 质量：证据引文逐字校验、置信度、事件时间窗、冲突复核、关系状态。
- 遗忘：召回衰减、失效标记、合并保留证据、软删除与撤销。

## 备份

- 核心包：SQLite 在线快照 + 配置 + 人设 + 会话，每日。
- 全量包：整个 `data/`（排除 venv/temp/logs），每周。
- 远端：百度网盘 xpan（应用目录 `/apps/<应用名>`）；上传后回读列表并校验字节数。
- 恢复：full → core，停止 AstrBot 后整包还原，WAL/SHM 必须一起。

## 刷新率与省电

- 聊天页主动向系统请求 `preferredDisplayModeId`（60/120）。
- 省电模式把动态 WebP/GIF 冻结在首帧，避免持续解码与纹理上传。
- 服务端 embedding 限制线程/并发与超时，避免超时重试风暴。
